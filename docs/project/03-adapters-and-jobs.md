# 03 适配器与后台任务规范

## 1. 适用范围与实现边界

本文落实开发计划第 3、4、8、9 章的外部调用、后台执行和资源治理要求，任务顺序以 [产品范围](01-product-scope.md) 为准，Run 状态与恢复语义见 [Agent 运行规范](02-agent-runtime.md)。文中的接口概念和阶段要求是实施约束，不代表已有对应实现。

- 当前 `service/agent/` 只有请求上下文和全局能力探测；`router/agent-router.go` 只注册只读能力探测，`runtime_ready` 固定为 `false`。
- `setting/agent_setting/config.go` 提供五项默认关闭的有效开关；`CanClaimNewWork` 是未来领取入口的检查点，尚不构成运行队列。
- `service/agentexecution/`、`service/mcp/`、`service/skill/`、`service/agentartifact/` 是计划中的落点，按对应任务建立，不为目录齐全提前生成空实现。
- 既有 `relay/` 供应商适配器、JavaScript 任务插件和系统任务继续按原契约运行；不能直接把它们标为 Agent 工具或客户脚本沙箱。
- `service/task_artifact_store.go` 的现有存储边界仍返回禁用实现，不能据此宣称 Agent 对象存储已可用。

## 2. 适配器边界

依赖方向遵循 [架构规范](04-architecture.md)。业务服务依赖最少的稳定接口；SDK 类型、网络响应和厂商错误留在适配器内部，不泄漏到公开 API、Run 状态或持久化检查点。

| 接口概念 | 最少职责 | 调用必须带入的服务端上下文 |
| --- | --- | --- |
| `ModelInvoker` | 调用、流式调用、查询原调用结果 | Run、step、logical call、attempt、租约代次、资金身份、输出上限 |
| `ToolExecutor` | 发现、校验、调用工具 | Workspace、连接及认证主体、工具快照、权限、审批回执、截止时间 |
| `SkillBackend` | 列元数据、取固定版本、受限读文件 | Workspace、version/digest、规范化路径、读取预算 |
| `ArtifactStore` | 写入、元数据、受控读取、删除、签发下载 | Workspace/Run、存储用途、大小限制、内容摘要 |
| `CheckpointStore` | 保存和加载安全恢复点 | runtime/state schema 版本、Run、租约代次 |
| `RunRepository` | 创建、领取、状态转换、追加事件 | Workspace 条件、revision/lease、明确事务边界 |

新增接口先证明真实调用点和实现差异，避免把一个函数拆成多层无语义包装。统一传递 `context.Context`，分别限制连接、响应头、读取和整体执行；响应体与流必须关闭。

适配器错误映射到计划中的稳定业务错误码，并说明可否安全重试。内部保留脱敏原因和关联 ID；不向用户透出含密钥 URL、原始请求头、堆栈或整段供应商响应。

## 3. 模型适配与资金边界

1. Agent 调用沿用既有网关的渠道、模型权限、限流、用量与结算管线；Worker 不绕过网关直连模型，也不自行再次扣费。
2. 浏览器运行绑定当前用户有权使用的 Team 资金 Token；公开运行的 caller Token 就是 funding Token，禁止请求体替换身份。
3. Worker 仅持有短期 Run 能力凭据；受保护 broker 验证服务身份、Run/step/call、租约、父 Token、模型范围和到期时间后解析父 Key。
4. broker 服务端生成网关请求关联，区分逻辑调用、broker attempt 与网关内部渠道 attempt；不能把不同层的自动重试叠加成无上限调用。
5. 已发送但结果未知的模型调用保留费用预留并转入核查；重试必须有未发出的确定事实，或可验证的供应商幂等/结果查询能力。
6. 模型返回只提供授权内容、可信用量事实和调用关联，不把上游 Key、父 Token 或隐藏推理链交给 Agent。

调用账本、预算与事务约束遵循 [运行规范](02-agent-runtime.md) 和 [数据库规范](05-database.md)，敏感财务操作遵循 [安全规范](06-security-and-permissions.md)。

## 4. MCP 连接与工具调用

- P04 首先开放经平台确认的只读工具；发现目录、声明 `readOnly` 或模型判断均不能单独证明无副作用。写工具必须满足 P06 的审批与恢复要求。
- 连接器分别处理连接测试、认证、协议协商、发现、Schema 校验和调用；官方 Go SDK 的接入版本在实施任务中固定并验证兼容性。
- 工具发现缓存按 Workspace、连接、认证主体隔离。模型只看到当前 Agent 获准的工具子集，不发送全平台工具目录。
- 每次调用重新验证当前授权、输入 Schema、风险类别、并发、输出大小、截止时间及出站目标；连接测试也必须执行同样的网络边界。
- 发布时记录工具 Schema 摘要。远端变化形成新快照；旧版本不兼容时要求重新验证，禁止静默套用新 Schema。
- 首期消费远程 HTTP MCP；stdio MCP 仅可在后续受控隔离进程中接入，不计入当前 108 项任务。对外发布 AIVale MCP Server 是另一个授权与接口任务。
- 工具返回内容是数据，不能作为更高优先级指令或追加权限。返回的 URL 不自动获得平台下载权限。

## 5. Skills 与脚本阶段

P05 支持技能包管理、固定版本及受限文件读取，可以收录脚本文件，但不得执行脚本。P08 通过隔离执行门禁后才开放脚本；工作流脚本节点还需完成 P09 对应适配。

1. 导入只接受 ZIP 或 Git 固定 commit；来源获取通过受控下载服务，不接受任意 shell 命令。
2. 校验包根目录、`SKILL.md` 前置字段、文件类型、路径、数量、单文件/总大小及压缩展开比例。具体安全检查见 [安全规范](06-security-and-permissions.md)。
3. 以规范化路径排序生成 manifest 和 digest；发布版本不可变，Agent 绑定具体 SkillVersion。
4. 先向模型提供名称和描述；激活后加载正文，引用文件按需读取并扣减读取预算，不能一次性装入整包。
5. `allowed-tools` 是作者声明，只能收紧平台权限。技能正文、依赖或安装提示不能授予网络、文件或命令执行能力。
6. 区分禁止新绑定与安全封禁；安全封禁在下一受控动作检查时阻断旧发布版本，审计保留受影响范围。

沙箱只允许运维审核的镜像/语言组合；按 Run 分配临时目录，限制 CPU、内存、进程数、磁盘、网络和墙钟时间。禁止特权、宿主 socket、平台数据库与全局云密钥；不能将普通 Docker 容器等同于已验证的租户隔离。

任务结束先上传允许的产物并核对 digest，再清理受管临时目录。终止失败、资源超限、输出发布失败均有明确状态与补偿入口，不能靠无限重启容器恢复。

## 6. 超时、重试与工具收据

| 操作 | 允许自动重试的前提 | 不确定结果的处置 |
| --- | --- | --- |
| 本地纯转换 | 固定输入、版本且无外部副作用 | 可从持久化输入重算 |
| 只读工具 | 平台确认可重试且结果新鲜度可接受 | 有界重试并记录每次 attempt |
| 模型调用 | 确认未发送，或存在可靠幂等/查询能力 | 停止新步骤，保留预算与原调用关联 |
| 外部写工具 | 对方支持稳定幂等键或可查询已执行结果 | Step 标为 `outcome_unknown`，进入核查 |
| 沙箱脚本 | 纯转换且输出未发布，或已有明确幂等语义 | 有外部写能力时按写工具处理 |

- 不重试认证失败、授权拒绝、Schema 错误或平台关闭；可重试操作采用有界次数、指数退避与抖动，总等待不能突破 Run 截止。
- 调用前保存执行意图；收据至少关联 Workspace、Run、step、logical call、attempt、工具/版本、参数 digest、审批 ID、租约代次、远端请求引用和结果状态。
- 收据只保存核查必需的脱敏摘要及授权产物引用，不保存完整认证头。重复回执按稳定关联去重，历史 attempt 不覆盖。
- 响应已到达后先持久化结果和收据，再发布完成事件与推进步骤；事件发送成功不能替代结果落库。
- 超时、连接中断、进程崩溃均不证明外部未执行。旧 Worker 租约失效只阻止旧代次数据库提交，不能撤回已经发出的请求。
- 未知外部结果不新增公开 Run 枚举；按计划置失败及明确错误。涉及费用时保留待核账状态，不通过再执行完整调用“补结果”。

## 7. 后台任务与调度

Run、领取租约、审批、调用意图与 outbox 以主数据库为准；Redis 只作唤醒、限流或短期缓存，丢失后可扫描恢复。不能把独立 ClickHouse 日志库用作抢占和业务事务存储。

- 多实例领取采用数据库条件更新，携带 `lease_epoch` 写入状态、事件和检查点；禁止先查后无条件更新。
- 调度器只创建持久化任务，Worker 执行步骤。扫描批量、线程池和队列有上限，超额进入明确排队或拒绝策略。
- 领取前检查 `CanClaimNewWork` 及当前租户准入；当前开关仅控制准入，不自动取消已进入的请求。真实排空和租约恢复在运行引擎任务中实现。
- 排队、累计执行、审批和总墙钟分别计时并落库；恢复不清零累计时间，不延长总截止。
- 审批等待释放执行槽；父子 Run 的协调等待按 [运行规范](02-agent-runtime.md) 处理，不能让单槽工作区因父占槽永久阻塞。
- 过期租约扫描先核查当前步骤的外部效果，不把所有任务直接重新入队；重试耗尽、outbox 死信、核查长期未解决均有告警和处理入口。

Schedule 固定 AgentVersion、输入模板、IANA 时区和资金 Token 引用。保存时校验 cron 并展示下一次触发；夏令时不存在时刻跳过，重复时刻按 UTC 计划实例去重。

每个计划时刻有唯一 fire 键，事务内创建 fire、Run 与 outbox。首期采用 `skip_if_running`，跳过也记录原因；恢复后默认不补全部历史触发，只允许明确有界的补跑策略。

Webhook 使用独立 hook secret 对原始 body 签名，结合时间戳和事件 ID 校验窗口及防重放。租户、Agent 版本、资金身份从已授权配置解析，不信任请求体覆盖；轮换记录 Key 版本和有限双 Key 窗口。入站只持久化 Run 并快速返回，不等待执行。

## 8. 产物、留存与资源治理

文件存储键由服务端生成；展示文件名不作为宿主路径。上传限制和下载授权必须基于 Workspace/Run，再按用途验证 MIME、内容、长度与摘要。对象链接只授予单个允许对象，不能复用模型 Token。

计划中的 Agent 下载采用短期签名或鉴权代理；`service/task_artifact_access.go` 的既有任务签名是另一套稳定能力凭据，不能直接当作具备过期与 Workspace 撤销能力的 Agent 下载接口。

以下是计划建议初值，待对应实现任务冻结和容量验证；尚未成为已有适配器的有效限制：

| 资源 | 初始约束 |
| --- | --- |
| 工具调用 | 默认 30 秒，且不超过 Run 剩余时间 |
| Skill 包 | 压缩 20 MiB、展开 100 MiB、1000 文件、单文本 2 MiB |
| 工具结果 | 网络接收 1 MiB、内联 32 KiB、序列化 TEXT 总量不超过 60 KiB |
| 产物下载 | 默认链接 60 秒，管理员上限 300 秒 |
| 内容留存 | 调试原文 7 天，普通运行内容与产物默认 30 天 |

文件能力实现前，工具结果超限须明确失败；实现后可转为授权产物，不静默截断结构化业务 JSON。资源次数、字节、并发、时间和费用分别计量，不能互相替代。

删除采用先标记、后异步 GC，并检查发布版本、检查点、审批、活跃下载和 `retention_hold`。对象删除与数据库引用非原子，须可重试并核查孤儿对象；未核账调用及必要财务关联不得随内容级联删除。

新增适配器必须验证取消、限流、超限、故障、授权撤销和恢复路径。验证与证据按 [测试与验收规范](07-acceptance.md) 执行，源码及产物的提交边界按 [Git 提交规范](08-git-commit.md) 与 [内容管理规范](09-repository-hygiene.md) 执行。
