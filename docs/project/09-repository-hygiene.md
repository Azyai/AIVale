# 09 仓库内容管理规范

## 1. 保留范围

项目目录只保留能说明用途的运行、开发、部署、契约与规范内容；不按文件数量或扩展名判断价值。

| 内容 | 处理规则 |
| --- | --- |
| 正式源码、运行资源、许可证与版权说明 | 保留并按正常规则版本管理 |
| `go.mod` / `go.sum`、前端依赖清单与锁文件、构建及测试运行配置 | 保留；取消测试跟踪不能破坏可复现构建 |
| `relaykit`、`tokenkit` 独立模块及其必要文件 | 保留独立构建能力，不能只验证根模块 |
| API、Schema、OpenAPI、声明文件、迁移、公开脱敏示例 | 按正式契约保留；被测试使用不改变其用途 |
| 必要部署脚本、配置模板、开发工具及工程规范 | 保留；与生成的部署包、真实配置或临时脚本区分 |
| 已确认开发计划 | 保留其内容和任务口径，不因目录整理擅自改写 |
| 有效测试源码、测试专用夹具和资源 | 仅本地保留和执行，由 Git 忽略 |
| 报告、日志、截图、测试结果、覆盖率、录屏、临时数据和生成归档 | 不进入 Git；无保留价值时清除本地副本 |

应用实际使用的图片、字体、示例或模板属于运行资源；不能把全部图片当截图、全部 JSON 当测试数据、全部 SQL 当数据库 dump。开发设计基准及其必要资源有明确用途时保留，失效原型、重复宣传材料和孤立素材应及时清理。

## 2. 本地与版本管理边界

- 忽略规则统一维护在 `new-api/.gitignore`；已经跟踪的内容必须另外取消跟踪，步骤见 [Git 提交规范](08-git-commit.md)。本地敏感配置、工具私有设置、依赖缓存与构建输出不提交。
- 新建本地产物目录前，用 `git check-ignore -v -- <路径>` 确认规则覆盖；命令日志、验收报告、截图和测试结果集中放入已忽略目录，不散落根目录、源码目录或规范目录。
- 正式文档只保留长期有效的设计与规则。一次性验收报告、批次执行记录和调查输出不因改成 Markdown、PDF、HTML 或压缩包而成为可提交规范。
- `web/dist` 是 Go 嵌入前端所需的本地构建产物，不进入 Git；清理后须先重新构建前端，再执行根 Go 构建。发布二进制、安装包、校验和及归档按发布流程生成，不作为源码提交。
- 测试仅本地保存不降低验证要求；新克隆与公共 CI 的能力边界见 [测试与验收规范](07-acceptance.md)。

## 3. 清理步骤与边界

1. 先检查 Git 状态、文件实际用途、代码和文档引用，区分有效源码、真实数据、生成产物及历史遗留。未跟踪或被忽略不等于可以删除。
2. 用户要求本地清理时，删除已确认无用的报告、日志、缓存、截图、生成包和杂物；已跟踪项同时从当前 Git 版本移除。有效测试通常只取消跟踪并保留本地，除非另有明确删除要求。
3. 不清空业务数据库、上传文件、备份、有效本地配置或运行中服务数据。删除路径必须先解析为绝对路径，并确认位于本次指定项目目录内；不要跨目录执行递归删除。
4. 删除或迁移文件后同步入口和引用，保留必要构建与开发工具。计划中的旧验收报告链接只标为历史引用，不为修复这些链接重新生成或提交报告。
5. 完成后核对保留文件、Git 差异、忽略命中和适用构建。清理结果在交付说明中简述，不再向仓库添加一份清理报告。

取消跟踪只影响当前及后续版本，不清除旧提交中的对象。普通整理通过新的变更完成，不自动重写 Git 历史或推送远端。
