# 10 模块分层与渐进迁移设计

版本：2026-11-06，开发设计稿。本文定义目标边界和迁移任务，不表示对应重构或新增能力已经完成。

与主计划新增 P12（顶部与首页）、P13（业务大厅）、P14（数据集资产）配套；既有 P00–P11 的任务事实、契约和验收要求继续有效。迁移任务使用独立 R01–R08 编号，不能通过完成 R 任务将业务 P 任务自动标为完成。

## 1. 设计结论

采用“模块化单体、按领域组织、在需要处建立层次”的路线。现有 Go 根模块、独立 `relaykit/`、`tokenkit/` 和 React 工程继续保留；先建立可运行的领域样板，再逐步收口旧包，不进行一次性全仓搬迁。

“产品”“业务大厅”“控制台”是用户入口，不各自拥有一份 Agent、Run、工作区或账务数据。业务大厅调用同一领域用例或读取授权投影；模型网关继续负责现有模型调用与计量，不能因新导航另建扣费链。

“包没有子目录”本身不是问题。需要治理的是职责混合、错误依赖、隐式全局状态和无法独立验证的用例；简单 DTO、枚举、纯函数不强行套四层结构。

## 3. 领域边界与数据所有权

| 领域 | 拥有的规则/资源 | 不承担的职责 |
| --- | --- | --- |
| platform navigation | 产品目录、入口、展示分组、兼容路由和能力状态映射 | 不授予资源访问，不持久化客户执行数据 |
| workspace | 工作区生命周期、成员、实时访问事实、现有 grant 管理 | 不持有模型余额或重新实现账户认证 |
| agent definition | 草稿、配置校验、不可变版本与发布指针 | 不管理运行租约、用户会话或供应商协议 |
| agent execution | Run、步骤、事件、检查点、租约、取消、恢复 | 不直接持有父模型 Token，不重复扣费 |
| automation | 客户计划、触发器、fire 去重、受理 Run | 不在扫描事务内执行 Agent，不复用系统维护队列 |
| approval | Run 中待批准动作、有效期、批准/拒绝及恢复授权 | 不成为泛化 OA，不把批准当永久权限 |
| business hall | 授权任务列表、待办聚合、跨入口跳转、业务查询投影 | 不成为第二套 Run 状态机，不拥有领域写表权限 |
| business task / bounty | business task拥有需求、交付、验收和Run关联；bounty拥有应榜、定榜及承接规则，作为前者的协作扩展 | 首期不做外部交易撮合、支付托管或开放悬赏市场 |
| dataset | 资产元数据、版本、文件清单、导入状态、授权与保留策略 | 不默认承担向量数据库、训练平台或模型权重托管 |
| model catalog | 现有模型展示、能力元数据、可用性与定价读取 | 不把现有模型目录扩大解释为模型训练/部署平台 |
| gateway / billing | 模型路由、协议适配、既有预扣/结算/退款和消费日志 | 不承担大厅业务流程，不由聚合统计反向触发扣费 |
| system maintenance | 平台内部维护任务、既有维护任务租约与执行 | 不接受客户 Run，不向普通客户暴露管理员任务 |

产品“Agent 智能调度”主要介绍执行与自动化能力；业务大厅“调度台”是同一能力的操作界面。产品“智能体工作台”承载构建与资源管理，不再单独复制一套任务中心。

## 4. 后端目标结构

目标采用现有顶层目录渐进分组。以下是迁移后的结构示意；没有实际用例时不预建空目录。

```text
router/                         路由装配，沿用现有前缀和中间件
middleware/                     HTTP 身份适配、准入 gate
controller/
  workspace/                    HTTP 请求解析与 DTO 输出
  businesshall/                 大厅查询入口
  ...                           旧 controller 文件保留为迁移接缝
service/
  workspace/
    application/                用例、窄端口、事务编排
    domain/                     纯状态规则、值对象、业务错误
  agentdefinition/              定义/版本领域；按复杂度增设子层
  agentexecution/               保留现有单步接口，按运行任务逐步扩展
  automation/ approval/ businesstask/ bounty/ dataset/ systemmaintenance/
repository/
  workspace/                    application 端口的 GORM/旧 model 适配
  agentdefinition/ systemmaintenance/ ...
model/                          旧 ORM 实体、迁移与已验证低层操作
integration/                    新增外部连接适配，必要时才建立
bootstrap/                      明确依赖装配与进程角色生命周期
pkg/                            无业务归属的可复用技术实现
types/                          既有边界契约，按兼容需要保留
relay/ relaykit/ tokenkit/       保持现有模块边界
```

`repository/agentdefinition`已用于Agent元数据读取；其余示意目录按实际用例创建。初期可以先在既有包内隔离函数和依赖，完成一个领域切片后再移动文件；禁止先批量移动后靠临时相互导入恢复编译。

### 4.1 依赖规则

```text
router → controller/<domain> → service/<domain>/application → domain
                                  ↓ 使用其自行定义的窄端口
bootstrap → repository/<domain> → 既有 model / GORM
bootstrap → 外部 integration    → HTTP / SDK / 对象存储
```

箭头表示源码依赖。`repository` 实现 application 所需端口；application 不导入 repository、controller、Gin 或 GORM。bootstrap 创建依赖并注入 controller。现有 `router → controller → service → model` 保留为迁移期结构，不要求一次性翻转所有旧代码。

- 端口定义在使用方，围绕业务操作命名；不建设 `BaseRepository[T]`、通用任意 SQL 或无差别 CRUD 工厂。
- domain 不依赖数据库、HTTP、SDK、全局配置和 `gin.Context`；简单领域不必单独建立 domain 包。
- application 接收 `context.Context`、可信身份引用和明确输入，不接收未验证的租户或角色声明。
- ORM、外部 SDK 和公开 DTO 分离；既有 DTO 未改协议时继续通过适配层输出。
- 一个目录对应一个 Go package；不能仅建子目录却继续假定可访问父包未导出符号。
- 每个跨域能力由拥有方提供窄服务入口；跨域流程由上层用例编排，不互相读取对方表或深层内部文件。
- `common/` 不继续收纳新业务规则；稳定通用函数才保留其中，领域专属函数随用例迁移。
- JSON 编解码继续遵守根模块 `common.*` 包装；不以分层为理由新建不同 JSON 协议。
- 不把完整父模型 Token、上游凭据或客户端可伪造的 Scope 当作应用接口通用参数。

### 4.2 工作区事务样板

工作区是高约束样板，目标不是把每条 SQL 包装一遍，而是让调用方表达“按当前事实执行一次工作区变更”。

1. controller 严格解析输入，取得已有管理会话产生的可信身份，调用 application。
2. application 经事务端口进入写操作；仓储适配复用现有 `WithAgentWorkspaceWriteFacts` 的锁顺序和重试边界。
3. 在同一短事务内读取当前身份、Team、Workspace、成员事实，application 计算动作许可和状态转换。
4. 同一事务保存业务变更、适用幂等收据和审计事实；提交后的日志投影仍独立恢复。
5. 端口不将 `*gorm.DB` 泄漏给 application；以业务所需的窄写会话暴露取事实、条件写、收据和审计操作。
6. 先迁内部定义查询/配置校验，再迁工作区写生命周期；全链路验证通过前旧适配是唯一生产写入口。

特别保留：实时授权、Team owner 双事实、revision/CAS、已归档幂等重放的特殊边界、未知提交结果不自动重放、三数据库行为。拆层不能把这些规则简化成前置角色判断。

### 4.3 业务大厅的读写路径

初期大厅按类型展示来源明确的任务，复用现有领域 API；如果后续要求跨源统一分页、统计或排序，新增有授权范围的查询投影/API，不能在浏览器拼接几个分页结果后声称全局总数正确。

统一列表至少保留 `source_kind`、原始对象 ID、工作区、原状态、展示状态与可执行动作；必须有未知状态和未就绪状态。展示状态只用于阅读，不能反向覆盖 Run 或供应商任务的原状态。

取消、重试、审批、触发计划分别调用所属领域命令；一次“批准”必须进入审批与执行的既有授权/版本检查，不能由大厅直接更新 `status`。大厅缓存和计数同样带主体、租户、工作区范围；无权限数据不先取全量再在前端过滤。

## 5. 前端目标分层

保留 `routes → features → components/lib`。现有 `features/<feature>/{components,hooks,lib,api.ts,types.ts}` 已经是有效基础，重点是约束跨域依赖和共享壳层。

```text
src/
  routes/                       URL、搜索参数、布局接入
  features/platform-catalog/    产品/大厅目录、入口解析；交互呈现复用公共layout
  features/agent-platform/      独立工作台壳与工作区上下文
    workspaces/                 团队/个人工作区 API、查询、表单
  features/agents/              按后续任务落地定义与发布
  features/agent-runs/           同一个 Run 页面被不同入口复用
  features/business-hall/        授权聚合、任务筛选与来源跳转
  features/automation/          计划与触发管理
  features/approvals/            待审批业务交互
  features/datasets/            P14 资产管理
  components/                   已有通用交互组件
  lib/                          API、公共格式化及中性工具
```

- public header、console header、agent workbench header 消费同一个导航视图模型；桌面与移动端可以不同布局，不能各自维护产品清单和权限条件。
- 产品注册表保存稳定 ID、翻译键、分组、描述、介绍页/操作页映射与能力依赖，不保存用户秘密或把导航布尔值当授权。
- 产品介绍可公开；操作入口同时检查该能力状态与当前授权。规划产品可以介绍其范围，不能点入空工作台冒充可用。
- API 与 DTO 校验归所属 feature；Query 管理服务端状态，Zustand 只保存确需跨页的客户端状态。
- `agent-platform/queries.ts` 按工作区用例渐进拆分；共享 capabilities 保持单一缓存语义，不复制多个探测端点。
- 通用 `section-registry` 工具从 system-settings 移至中性目录后，保留业务 section 配置；不建立承载全部页面业务的万能注册器。
- 旧地址、查询条件、登录后安全回跳、工作区深链接保持兼容；路由迁移和数据迁移分别处理。
- 复用已有导航、侧栏、弹层、空错态和基础控件；实现前读取适用前端规范及现有调用例。

所有 R 任务当前为“设计待实施”。每批必须可独立构建、灰度及回退；业务新增与纯结构迁移分开说明。

| R05 大厅领域接入 | Run 聚合读模型；审批、客户计划和内部揭榜按各自领域接入 | 对齐 P13 及 P03/P06/P07 就绪条件；不共用维护任务表 | 跨源分页真实性、权限范围、旧状态保留、命令回所属领域 |
| R06 数据集资产切片 | Dataset 元数据/版本仓储、存储适配、API 与前端领域模块 | 对齐 P14；检索/索引对接另依赖 P10 | 租户隔离、不可变版本、导入失败、删除保留、三库与存储一致性 |
| R07 网关与账务收口 | 在业务需要时按渠道、模型目录、路由策略、账务逐个建立窄服务 | 排在已验证样板之后；单独子批次，保持 relaykit/tokenkit 独立 | 模型协议、流式取消、真实费用来源、数值边界、重试和结算不变 |
| R08 收敛与依赖门禁 | 移除已无消费者的旧 facade，收紧新增越层引用，更新规范和依赖例外 | 每个已迁领域可滚动执行；不是等全仓搬完再检查 | 无循环依赖、无双写权威、兼容入口有明确生命周期、未迁部分仍可运行 |

### 6.1 每次切片的固定顺序

1. 列出行为与契约，确认调用者、数据库影响和本地用例是否齐全。
2. 在拥有方定义最小用例接口；先用现有实现适配，不改变外部行为。
3. 将纯规则与外部访问分离，装配从入口显式完成；仍只保留一个生产写路径。
4. 切换一个调用面，执行对应回归；必要时短期保留旧函数作为兼容 facade。
5. 旧消费者归零后删除 facade 和无效导出，更新规范；不能长期双实现分叉。

## 7. 数据、接口与回退约束

- 拆包默认不改表名、列名、ID、时间单位、状态枚举或公开响应；目录名变化不意味着需要数据库迁移。
- 对新表/新字段采用可兼容的增量迁移；历史回填分批、可重入，有明确读写切换条件。回退业务代码不自动执行破坏性降级迁移。
- 同一领域只有一个写入权威。临时读投影允许异步更新，但需明确水位和陈旧状态；不使用无校验双写掩盖迁移失败。
- 新应用层错误由 controller 映射为原错误 wire，保留已有 HTTP 状态、`success/message/data` 与 Agent `code/request_id` 契约。
- 保持 SQLite、MySQL、PostgreSQL 主库支持；独立日志库不能承担业务幂等、租约或原子性。
- 只要改变真实查询、事务、迁移或驱动行为，就执行适用真实三库矩阵；纯文件移动仍应检查初始化顺序与 ORM 注册未变化。
- Worker、调度扫描器的进程装配随原运行任务冻结；不能借本次拆层自行替换已有部署角色含义。
- 客户任务、供应商异步任务、系统维护任务保留不同身份、状态机和恢复语义，最多共享受约束的技术组件。
- 与账务相关的切片先读 `.agents/rules/billing.md`，表达式工作另读 `pkg/billingexpr/expr.md`；模型费用继续由原网关产生，Run 汇总不再次扣款。
- 认证切片若实际调整流程，按 `AGENTS.md` 要求查阅当时稳定 OWASP 指引并执行专项验证；本次分层设计不授权替换认证机制。

## 8. 验收与架构门禁

### 8.1 必需行为证据

| 变更范围 | 最小验证 |
| --- | --- |
| 纯模块/装配调整 | 受影响用例回归、真实路由契约、初始化/退出行为、`go vet` 与构建 |
| 工作区/定义仓储 | 原 P01/P02 适用门禁，实时身份、跨租户、版本冲突、幂等和三库事务 |
| 维护任务 | 调度周期、并发领取、租约过期、重启恢复、取消、错误记录与管理权限 |
| 大厅聚合 | 授权先于分页/统计、来源状态映射、未知状态、跨入口动作一致性 |
| 导航/首页 | 受影响前端类型/lint/build、桌面/窄屏、键盘、语言主题、旧链接、能力异常状态 |
| 网关/账务 | 协议与 SSE、数量边界、预扣/结算/退款、重试、未知结果、团队/个人资金不串用 |
| 独立 Go 模块 | 影响到模块或公开 API 时分别 `GOWORK=off go build ./...` 和 `go vet ./...` |

根 Go 构建前须有真实 `web/dist`；不能创建空资源伪造通过。测试源码和夹具按仓库约定本地保留、Git 忽略，公开 CI 构建不代替测试。缺用例、数据库或环境时明确记为未验证。

### 8.2 新增依赖的增量约束

后续实现依赖检查时，先记录存量例外，只禁止新增反向依赖；每迁完一个领域减少一项例外。不为通过检查把旧依赖藏进万能接口、字符串反射或 `common`。

- 新 controller 不执行 GORM 查询、不实现后台调度循环。
- 新 application 不导入 Gin、GORM、controller 或外部 SDK。
- 新 domain 保持纯规则，不读全局 Option、数据库或网络。
- 新 repository 不调用 controller 或启动后台任务。
- 前端 feature 不深度导入另一 feature 的内部工具；共享能力通过明确导出或中性公共模块使用。
- `relaykit` 不依赖根模块；`tokenkit` 不依赖根模块或 `relaykit`。
