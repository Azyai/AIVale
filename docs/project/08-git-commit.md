# 08 Git 提交规范

## 1. 原子提交与授权

- 实际仓库为 `new-api`。操作前检查当前分支、`git status --short`、暂存差异及改动归属，不覆盖或夹带其他工作。
- 一个提交表达一个可独立审查的任务、行为或规范主题。实现、必要契约、配置和迁移构成完整变更时一起提交；无关重构、格式化和临时文件分别处理。
- 按依赖顺序提交，跨模块变更同步契约与使用方。每批保持适用构建可通过；验证范围及未运行项按 [测试与验收规范](07-acceptance.md) 说明。
- 只有用户明确授权时才创建提交；不自动 push，不自动改写共享历史，不使用强制推送处理普通清理。清除当前版本的文件，通过新的删除提交完成，不把含有业务实现的整批历史提交一并撤销。

## 2. 中文提交信息

```text
<type>(<scope>): <中文摘要>

<中文正文：原因、行为变化、关联任务、实际验证及限制>
```

常用 type 为 `feat`、`fix`、`refactor`、`docs`、`build`、`ci`、`perf`、`chore`；scope 使用真实模块或主题，如 `agent-runtime`、`web-workspace`、`relaykit`、`docs-git`。摘要及正文使用中文，必要的技术名称和任务编号保留原文。已有提交不为语言统一而改写。

正文只记录可审查的验证摘要，不粘贴整份验收报告或命令日志。任务编号存在时准确关联，不编造编号，不把未运行项描述为通过。

## 3. 取消测试与产物跟踪

测试源码和测试专用夹具仅保留本地；已跟踪的有效测试使用以下方式取消跟踪，并保留本地内容及未提交修改：

```bash
git rm --cached -- <已核对的具体测试文件>
```

同时维护仓库 `.gitignore`，防止再次进入暂存区，不使用 `git add -f` 绕过。验收报告、日志、截图、测试输出和无用产物也应取消跟踪；用户明确要求本地清理时，对已确认无用的文件同时删除本地副本。

`.gitignore` 不会自动停止跟踪已有文件。也不能仅按 `test`、`report` 等字样批量删除：生产测试连接接口、Schema、OpenAPI、公共示例、迁移、构建文件、锁文件和测试运行配置应按实际用途保留。分类规则见 [仓库内容管理](09-repository-hygiene.md)。

## 4. 提交前核对

1. 用 `git diff --cached --name-status` 检查文件范围，再用 `git diff --cached` 检查实际内容；部分暂存时逐块核对。
2. 暂存区不含测试源码及专用夹具、验收报告、日志、截图、覆盖率、临时数据库、构建包、真实业务数据或凭据。
3. 有效本地测试及其修改仍在；测试所需依赖、配置和正式契约没有因取消跟踪而误删。
4. 受影响构建与本地验证已按实际范围执行；缺少用例或环境时明确说明，不以公共 CI 结果代替验收。
5. 文档或文件删除后检查引用；外层规范与仓库 `docs/project/` 镜像同步。已确认计划中的旧报告引用按历史引用处理，不据此恢复报告入库。
6. 确认本次提交已获明确授权，并且不混入其他未授权工作。提交完成后再次检查状态，不自动推送。
